RAFIDPAY · MERCHANT API

توثيق الربط الحقيقي — RafidPay LIVE

اربط موقعك ببوابة RafidPay لإنشاء فواتير، وفتح صفحة دفع العميل عبر مزود الدفع إيصالات (Esaalat)، ثم متابعة حالة التحصيل المؤكدة.

LIVE · ESAALAT

1. قبل البدء

  1. أنشئ حساب تاجر في RafidPay وسجّل الدخول.
  2. أكمل متطلبات التفعيل وانتظر اعتماد حساب التاجر من الإدارة.
  3. أنشئ مفتاح API من لوحة التاجر، واحفظه في الخادم الخلفي لموقعك.

لا تضع مفتاح API داخل JavaScript في المتصفح أو تطبيق العميل. أرسل طلبات API من Backend موقعك فقط.

2. المصادقة

Authorization: Bearer rp_live_YOUR_API_KEY
Content-Type: application/json
Authorization: Bearer rp_live_YOUR_API_KEY

كل طلبات /api/rafidpay/v1/ تتطلب مفتاح تاجر صالحاً وحساباً بحالة active.

3. إنشاء فاتورة دفع

POST /api/rafidpay/v1/payment-links
{
  "title": "Order #102",
  "description": "Customer order",
  "amount": 2500,
  "currency": "YER"
}

المبلغ يجب أن يكون عدداً صحيحاً موجباً بالريال اليمني؛ هذا هو نطاق التحصيل المباشر المتاح حالياً عبر إيصالات.

استجابة ناجحة — 201

{
  "payment_link": {
    "id": 12,
    "slug": "32-character-link-token",
    "title": "Order #102",
    "amount": "2500",
    "currency": "YER",
    "status": "active",
    "mode": "live",
    "url": "https://YOUR_DOMAIN/rafidpay/pay/SLUG"
  }
}

أرسل رابط payment_link.url للعميل أو اعرضه له في صفحة الطلب.

4. إنشاء طلب تحصيل حقيقي لدى إيصالات

POST /api/rafidpay/v1/payment-links/{slug}/orders
{
  "customer_name": "Customer Name",
  "customer_email": "customer@example.com"
}

ينفذ هذا المسار من خادم متجرك بعد مصادقة API. ينشئ طلباً لدى إيصالات ويربطه بالفاتورة والتاجر.

استجابة ناجحة — 201

{
  "order": {
    "reference": "RPE_...",
    "amount": "2500",
    "currency": "YER",
    "status": "pending",
    "title": "Order #102",
    "intent_id": "ESAALAT_INTENT_ID",
    "checkout_url": "https://...",
    "wallet": {
      "name": "Collection Wallet",
      "account_number": "..."
    }
  },
  "payment_url": "https://YOUR_DOMAIN/rafidpay/pay/SLUG"
}

لواجهة العميل، استخدم payment_url؛ صفحة RafidPay Checkout تنشئ طلب الدفع وتعرض تدفق الدفع المباشر عبر تكامل إيصالات.

لا تعتبر إنشاء الطلب نجاحاً مالياً. تبقى الحالة pending حتى يؤكد مزود الدفع العملية.

5. التحقق من حالة عملية

GET /api/rafidpay/v1/transactions/{reference}
Authorization: Bearer rp_live_YOUR_API_KEY

استجابة

{
  "transaction": {
    "reference": "RPE_...",
    "status": "paid",
    "amount": "2500",
    "currency": "YER",
    "payment_mode": "live",
    "created_at": "...",
    "paid_at": "..."
  }
}

الحالات الممكنة تشمل pending وpaid وfailed وrefunded. اعتبر الطلب مدفوعاً فقط عندما تكون الحالة paid.

يمكن لمتجرك الاستعلام دورياً من الخادم عن حالة المرجع حتى تتغير إلى paid.

6. استعراض الفواتير والعمليات

GET /api/rafidpay/v1/payment-links
GET /api/rafidpay/v1/transactions

تعيد هذه المسارات آخر 100 فاتورة أو عملية تخص التاجر صاحب المفتاح.

7. مثال Node.js — إنشاء فاتورة

const base = "https://YOUR_DOMAIN";
const apiKey = process.env.RAFIDPAY_API_KEY;

const response = await fetch(base + "/api/rafidpay/v1/payment-links", {
  method: "POST",
  headers: {
    "Authorization": "Bearer " + apiKey,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    title: "Order #102",
    description: "Customer order",
    amount: 2500,
    currency: "YER"
  })
});

const data = await response.json();
if (!response.ok) throw new Error(data.message || data.error);
console.log("Send this checkout URL to the customer:", data.payment_link.url);

8. مثال Node.js — متابعة الدفع

const reference = "RPE_REFERENCE_FROM_YOUR_ORDER";

const response = await fetch(
  base + "/api/rafidpay/v1/transactions/" + encodeURIComponent(reference),
  { headers: { "Authorization": "Bearer " + apiKey } }
);

const data = await response.json();
if (!response.ok) throw new Error(data.message || data.error);

if (data.transaction.status === "paid") {
  // Mark your local order as paid on your server.
}

9. رموز الأخطاء

  • 401 INVALID_API_KEY — مفتاح غير صالح.
  • 403 MERCHANT_NOT_ACTIVE — حساب التاجر غير مفعل.
  • 404 PAYMENT_LINK_NOT_FOUND — رابط الفاتورة غير موجود أو لا يخص هذا التاجر.
  • 404 TRANSACTION_NOT_FOUND — مرجع العملية غير موجود ضمن حساب التاجر.
  • 400 ESAALAT_REQUIRES_WHOLE_YER_AMOUNT — يلزم مبلغ صحيح بالريال اليمني.
  • 503 ESAALAT_WALLET_NOT_FOUND — تعذر تحديد محفظة التحصيل.

10. ملاحظات التكامل

  • التحصيل المباشر في هذا التكامل يستخدم إيصالات (Esaalat).
  • العملة المدعومة في مسار التحصيل الحالي: YER وبمبلغ صحيح دون كسور.
  • تأكيد الدفع يعتمد على حالة العملية التي يسجلها RafidPay بعد تحقق مزود الدفع.
  • واجهة API الحالية توفر الاستعلام عن الحالة (Polling)؛ لا يوجد حالياً Webhook صادر إلى موقع التاجر، لذلك لا تبنِ تكاملك على استقبال Callback من RafidPay.
  • مسار sandbox-pay منفصل للاختبار البرمجي ولا يمثل عملية تحصيل فعلية.
